# P0 fixes - 2026-06-11

## Qué se arregló

Se cerraron tres bloqueos P0 detectados en la auditoría diaria:

1. `historial_examenes` queda versionada en migraciones con RLS e índices.
2. `flashcards` acepta `historia_filosofia`, igual que la UI de La Zona.
3. Los prompts de IA de Planning y Simulacros dejan de llamar Madrid a usuarios de Cataluña.

## Migraciones creadas

- `20260611120000_create_historial_examenes.sql`
  - Crea `public.historial_examenes` si no existe.
  - Asegura columnas usadas por el código: `user_id`, `asignatura`, `tipo`, `año`, `bloque`, `opcion`, `nota`, `nota_maxima`, `enunciado`, `respuesta`, `correccion`, `created_at`, `updated_at`.
  - Activa RLS.
  - Policies: SELECT, INSERT, UPDATE y DELETE limitadas a `auth.uid() = user_id`.
  - Índices: `(user_id, created_at desc)` y `(user_id, asignatura, created_at desc)`.
  - No borra datos ni trunca correcciones.

- `20260611120500_allow_historia_filosofia_flashcards.sql`
  - Actualiza `flashcards_subject_check` manteniendo los subjects existentes.
  - Añade `historia_filosofia`.

## Prompts de comunidad

- `app/planning/page.tsx`: el prompt usa `EBAU Madrid` o `PAU Catalunya` según `useCCAA()`.
- `app/api/simulacro/route.ts`: el system prompt usa la comunidad del simulacro, inferida desde el payload o los bloques guardados.

## Cómo validar

1. Ejecutar migraciones en Supabase.
2. Crear una flashcard de Historia de la Filosofía.
3. Generar Planning con comunidad Madrid y Cataluña.
4. Corregir un simulacro creado en Cataluña y comprobar que el prompt usa `PAU Catalunya`.
5. Ejecutar `npm run build`.

- Añadir tests automatizados para prompts por comunidad y constraints críticas cuando exista suite de tests.
